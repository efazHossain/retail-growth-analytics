# Data Model

This project follows a simple medallion-style analytics workflow:

```text
raw CSVs -> staging models -> dimensional marts -> dashboard and written analysis
```

## Raw Layer

The raw layer simulates source-system exports.

- `data/raw/customers.csv`
- `data/raw/orders.csv`

These files are regenerated by `node scripts/generate-data.js`.

## Staging Layer

The staging layer standardizes source data and adds low-level derived fields.

- `stg_customers`: cleaned customer IDs, region, segment, signup date, signup month
- `stg_orders`: cleaned order records with numeric revenue, cost, profit, order month, discount rate, and fulfillment days
- `stg_categories`: category lookup table

Staging is built by `node scripts/build-staging.js`.

## Mart Layer

The mart layer contains reusable business-ready models.

- `dim_customers`: customer attributes plus lifetime order, revenue, and profit metrics
- `dim_categories`: product category dimension
- `fact_orders`: order-level fact table with foreign keys and metric fields
- `mart_monthly_revenue`: monthly KPI reporting table
- `mart_channel_performance`: channel revenue, profit, discount, and fulfillment performance
- `mart_regional_margin`: regional profitability table
- `mart_category_performance`: category-level performance table
- `mart_cohort_retention`: customer cohort retention table
- `mart_revenue_forecast`: simple trend-based forecast table
- `mart_forecast_backtest`: rolling forecast versus actual revenue comparison
- `mart_forecast_accuracy`: forecast accuracy summary metrics

Marts are built by `node scripts/build-marts.js`.

## Why This Shape

The project is intentionally structured like a small warehouse workflow. Staging keeps raw cleanup separate from business logic, facts and dimensions make joins predictable, and marts make dashboard metrics reusable instead of recalculated differently in each chart.
